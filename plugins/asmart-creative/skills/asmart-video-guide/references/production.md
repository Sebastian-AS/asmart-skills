# Production choices

For a procedural tutorial, show the actual sequence, relevant cursor motion and observable result. For onboarding, orient the viewer to a main task without covering every feature. For a preview, connect an observed capability to a use and result. For a concept, use diagrams or prepared examples and identify them.

Choose pacing and framing for the viewer and channel. Neither a WhatsApp preview nor an internal help guide has a universal duration. Assign timings after rehearsing or capturing the action and narration.

Use the chosen renderer's project format. Keep original captures, editable crops, shot plan, source inventory and local media. Each shot should identify its screen or source, action, explanatory text, result and capture status. Preserve font and media licenses.

Keep controls and results legible. Establish spatial context before a zoom; let clicks have visible consequences. Avoid decorative motion over instructional text. Preserve the source application.

Distinguish narration subtitles from instructional labels. Do not call labels a transcript. Use the user's recording, a permitted synthetic voice or silence according to the brief; do not imply synthetic speech is the user's real voice. Match sound and visual timing after wording stabilizes.

For HyperFrames, read its installed entrypoint and current route before authoring. Use an available compatible runtime without changing the user's default unnecessarily. Load only the needed domains.

For course capsules and presentations, the navigable web module is the primary product; use [web-module.md](web-module.md). The same scenes supply any complementary MP4. Do not carry customer conversations, course-specific rules or private data into unrelated videos.
