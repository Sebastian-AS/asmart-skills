# Discover the platform

Use the supplied URL, authorized browser session, repository, documentation, screenshots or local project. Inspect available sources before asking for information already present.

Record the product's purpose, target role, task entry, required input and completion signal. Separate observed functionality, documented-only behavior, planned features and prepared examples. Record date and version or commit when available.

For an unfamiliar product, walk one user journey first. Read controls and help; inspect relevant source or official documentation where UI behavior is unclear. Do not infer backend features from branding or screenshots.

ASmartSolution skills may provide identity assets and project leads. Verify each lead. A folder named Campus is not proof the requested product is Campus. Avoid hardcoding a particular user's machine paths into the workflow.

Use actual UI for walkthroughs. An HTML recreation is appropriate for a requested prototype or conceptual animation, but does not prove live behavior. State which prepared parts do not execute the external service.

Use authorized roles and demonstration data. Do not print secrets or private records in reports. If required access is missing, prepare the script and shot plan and ask for the specific access step. Recording a workflow does not authorize its consequential mutations; use an approved test environment or an explicitly authorized demo action.
